# QuietQuorum Devpost draft

Updated November 24, 2026 for the working prototype. This does not represent a final hackathon submission.

## Project name

QuietQuorum

## Elevator pitch

Turn private interview notes into evidence-backed findings, offline first, without losing the voices that disagree.

## Inspiration

A community consultation can end with a confident summary that hides the people whose needs differ from the majority. Meanwhile, the original notes can contain details that participants did not expect to be sent to an AI service.

QuietQuorum helps small community organizations turn interviews into findings they can inspect: what people said, which voices support a theme, and which voices challenge it.

## What it does

QuietQuorum is a working Web/Chrome prototype for #BuildHybridAI 2026. A researcher can capture notes locally, use on-device AI to suggest exact-quote evidence cards, redact shared excerpts and review the exact payload before sending it to cloud AI. After the first online visit and application caching, capture and review work offline.

Cloud synthesis compares approved cards across interviews. Findings link to supporting evidence, possible counterevidence and local source notes. The interface shows both source passages without full-sentence evidence cards and approved excerpts omitted from synthesis. Participant counts are calculated from source IDs rather than generated by the model. Editing a shared excerpt revokes its approval; changing the outgoing evidence makes existing findings stale and blocks report export until new findings are reviewed.

The demonstration uses six fictional participants discussing a community workshop. Four prefer Saturday while two cannot attend. A repeated Saturday preference from the same person counts once. A clearly labeled written example is available without AI access; live AI results are separately identified.

## How we built it

The stack is TypeScript, React, Vite, IndexedDB, Firebase AI Logic, Firebase App Check and Firebase Hosting. On-device extraction and cloud synthesis use the same Firebase AI Logic SDK with explicit ONLY_ON_DEVICE and ONLY_IN_CLOUD modes. The application checks the SDK's inference-source metadata before accepting results. Raw-note processing has no cloud fallback. App Check is enforced, with a production reCAPTCHA Enterprise provider registered for the hosting domains.

The primary target is desktop Chrome. Offline local AI requires compatible hardware and a downloaded model. Manual capture and excerpt creation remain available when local AI is unavailable. Original notes are stored locally and are not encrypted by this prototype; researchers must review shared content for identifying details.

## Current progress

The prototype is deployed at https://quietquorum-358a5.web.app. Real on-device extraction, offline local inference and cloud synthesis have been verified using fictional interviews. A live cloud request from the public app succeeded with production App Check. The release passes 61 automated tests, 16 Chrome workflow checks and a separate network-blocked reload. Researchers can link repeat interviews, edit findings, reclassify evidence and preview printable reports. This is small-scale functional verification, not a model-quality benchmark. The [working demonstration](https://youtu.be/ZtYqxEungjs) is public. Prospective-user testing remains outstanding.

## Challenges we are working on

An early local test missed a negative constraint. We improved the prompt and output schema and added a visible list of source passages not covered by cards. A cloud test misclassified a citation even though its ID was valid. These failures reinforced the need for visible evidence, bounded claims and human review. A citation establishes provenance, not interpretive correctness.

## What is next

Test the correction workflow with prospective users, and verify the remaining entrant declarations before final submission. The held-out evaluation covers 22 fictional scenarios and preserves quota errors and semantic limitations.
