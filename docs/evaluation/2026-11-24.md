## Local extraction

The six cases covered negative constraints, conditional accessibility plus private contact details, repetition, an embedded instruction attack, uncertain attendance and an exploratory Arabic note. All required source sentences were recovered, repeated quotes were deduplicated, the contact email was excluded, and the instruction attack was not selected as evidence. Observed latency ranged from about 11.8 to 50.7 seconds. The slowest run coincided with heavy memory pressure on this 8 GB machine. This is a demo/usability risk even though extraction succeeded.

The Arabic example passed, but the application currently requests English model input/output support. One successful Arabic probe is not a multilingual-support claim. Offline local inference had passed previously; these six extraction probes ran online with SDK metadata confirming on-device inference.

## What failed and what changed

**Source coverage bug fixed:** A note containing multiple lines without full stops could lose an earlier line from the uncovered-passages list. A failing regression test reproduced this. The parser now treats line endings as passage boundaries; the regression and browser check pass.

**Cloud interpretation remains imperfect:** Baseline accessibility results incorrectly treated another participant's ability to use stairs as counterevidence to someone needing a ramp, and inferred wheelchair use. Another result added “online-only” to a preference for online registration. Valid IDs did not prevent these semantic errors.

The revised prompt distinguishes coexisting needs from opposition, prevents unsupported exclusivity and attributes, and applies evidence rules to titles as well as summaries. Both repeated accessibility cases and both registration cases then met the rubric. However, the revised prompt still produced false counterevidence in two scheduling runs and one transport run. The transport run also inferred not owning a car from not driving. Some outputs split related support across separate findings, reducing the usefulness of the counts even when each narrow claim was defensible.

There is no claim that prompt changes solved these problems. The UI labels counterevidence as possible and requires review before export, but the present correction workflow is inadequate: researchers cannot yet edit a draft finding and its citation roles directly. That is the highest-priority product improvement before recording the final demo.

## Browser checks

The isolated preview on port 4174 was used so testing did not replace the user's live workspace. Checks covered an empty study, disabled extraction for empty notes, rejection of invented manual quotes, visibility of omitted unpunctuated constraints, HTML-as-text rendering, approved-only payload construction, private-field exclusion, card invalidation after source editing, cancellation of deletion, deleting the final note, oversized import rejection and successful text import. A subsequent network-blocked reload preserved the imported note and question.

Earlier checks also covered reviewed report export, stale-export blocking, participant deduplication, responsive layout and the hosted App Check/cloud path. The raw results contain only synthetic excerpts and no credentials.
